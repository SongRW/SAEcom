# 脚本导入设计

- 日期：2026-07-31
- 分支：develop_srw
- 类型：脚本编辑器功能补全
- 影响范围：脚本编辑器工具栏、脚本 IPC、预加载类型、单元测试、Electron E2E

## 背景

脚本编辑器当前支持将活动脚本导出为 `.js` 文件，但没有将导出的文件重新导入用户脚本目录的入口。用户需要在脚本页导入 `.js` 文件，并且导入不应覆盖已有同名脚本。

## 目标

1. 脚本编辑器工具栏提供“导入”按钮。
2. 用户只能在原生选择器中选择 `.js` 文件。
3. 导入后的脚本写入应用 userData 下的 `scripts/` 目录。
4. 同名脚本保留，导入文件自动命名为 `名称 (1).js`、`名称 (2).js`，直到名称可用。
5. 成功导入后刷新脚本列表、自动打开导入的脚本，并显示最终文件名。
6. 取消文件选择不显示错误；读取或写入失败显示错误。

## 设计

### 主进程 IPC

新增 `scripts:import` IPC，由主进程完成整个导入事务：

1. 调用 `dialog.showOpenDialog`，仅接受一个现有 `.js` 文件。
2. 用户取消时返回 `{ ok: false, canceled: true }`。
3. 从选择的文件读取 UTF-8 文本。
4. 使用已有 `safeScriptName` 规范化原始文件名，再从 `.js` 基名推导目标名。
5. 检查 `scriptsDir`：原名已存在时，按 `名称 (1).js` 递增生成首个不存在的名称。
6. 写入目标文件后返回 `{ ok: true, name: finalName }`；捕获文件系统异常并返回 `{ ok: false, error }`。

渲染进程不会接收文件路径，也不会取得任意本地文件读取能力。导入内容不执行、不解析、不重写，和当前导出的原始 `.js` 文本保持对称。

### 渲染交互

`ScriptsAPI` 和 preload 增加 `importScript()`。脚本编辑器的 `Toolbar` 在“导出”旁增加使用现有图标库的“导入”命令。点击后：

- 调用 IPC；取消时静默返回。
- 成功时刷新脚本列表，选择并加载返回的最终名称，提示“已导入：最终文件名”。
- 失败时显示“导入失败：返回的错误说明”。

脚本列表右键菜单保持现有逐项操作；导入是作用于整个脚本库的工具栏命令，不依赖当前活动脚本。

## 测试与验证

1. 为纯命名逻辑提供单元测试：无冲突、一次冲突、多次冲突、含扩展名和不含扩展名的原始名称。
2. 为主进程导入逻辑测试取消、读取错误和成功写入可覆盖的路径；将无副作用的逻辑提取为可单测函数，避免直接调用 Electron dialog。
3. 新增 Playwright Electron E2E：在测试临时目录写一个 `.js` 文件，经“导入”按钮导入，验证列表/活动脚本内容；再次导入同一文件，验证原脚本存在且自动生成 ` (1)` 副本。
4. 运行 `npm test`、`npm run typecheck`、`npm run test:e2e:build`。现有与本次无关的 Rete 注册表计数断言失败需单独记录，不通过修改其期望值掩盖。

## 非目标

- 不支持批量导入、拖放导入、`.txt` 或其他脚本格式。
- 不导入命令、面板配置、日志或 Modbus 配置。
- 不覆盖同名脚本，也不提供导入时手动重命名对话框。
- 不执行、语法检查或迁移导入文件内容。
